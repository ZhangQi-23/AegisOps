# AegisOps — 企业智能运维知识助手

AegisOps 是一个面向企业运维场景的智能知识助手，结合检索增强生成（RAG）、大语言模型和 Agent 工具调用，实现运维知识检索、智能问答及 Redis 运行状态诊断。

项目采用 FastAPI 构建后端服务，通过结构化数据库、缓存、向量检索和大模型协作，探索企业知识管理与智能运维的结合方式。

## 一、项目功能

### 1. 用户认证与权限管理
- 用户注册、登录与密码哈希存储。
- 基于 JWT 的身份认证。
- 通过用户身份校验知识库访问权限。

### 2. 知识库与文档管理
- 支持知识库的创建、查询、更新和删除。
- 支持 TXT 文档上传与文件大小、类型校验。
- 对文档进行文本切分，并将文本块保存至 MySQL。
- 生成文本向量并存储至 Chroma，支持语义检索。

### 3. RAG 智能问答
- 根据用户问题检索知识库中的相关文本片段。
- 将检索结果组织为上下文，交由大语言模型生成回答。
- 返回回答、检索数量及来源片段。
- 使用 Redis 缓存符合条件的问答结果，减少重复请求的开销。
- 对无相关资料的场景进行处理，避免将缺乏依据的内容作为知识库事实。

### 4. Agent 智能运维诊断
- 基于模型工具调用机制执行预定义的运维诊断工具。
- 支持查询 Redis 连接状态、内存指标、服务版本及运行信息。
- 将工具执行结果交由模型分析并生成中文诊断报告。
- 通过工具白名单、参数校验和调用轮数限制控制执行范围。

### 5. RAG + Agent 联合诊断
- 检索知识库中的运维手册和相关建议。
- 获取 Redis 的实时诊断数据。
- 综合知识库资料与工具返回结果生成诊断报告。
- 区分文档中的参考信息与实际监测数据。

### 6. 多轮对话
- 支持基于会话历史的连续问答。
- 对历史消息进行筛选和长度限制。
- 保存用户与助手的对话记录。

| Git / GitHub | 版本管理与代码托管 |

## 三、核心业务流程

### RAG 问答

1. 用户提交问题。
2. 对问题进行向量化。
3. 从指定知识库检索相关文本片段。
4. 将检索结果组织为上下文。
5. 调用 DeepSeek 生成回答。
6. 返回回答、来源信息，并在符合条件时缓存结果。

### Agent 运维诊断

1. 用户提交运维问题。
2. 模型根据问题和可用工具定义决定是否调用工具。
3. 后端校验工具名称和参数。
4. 执行只读诊断工具并获取实际结果。
5. 将工具结果交还模型进行分析。
6. 返回诊断结论、工具调用记录及执行状态。

### RAG + Agent 联合诊断

知识库检索提供运维手册和处理建议，Agent 工具提供实际运行数据。两类信息相互补充，使回答既能参考已有知识，也能结合当前环境的诊断结果。

```text
AI-Knowledge-Agent/
├── .gitignore

    ├── app/

    │   ├── schemas/      # 请求与响应模型
```

`uploads/` 与 `chroma_db/` 为运行时本地数据目录，不应提交包含用户文档或本地数据库数据的文件。

## 五、环境配置

### 1. 环境要求

- Python 3.10 或兼容的项目 Python 版本
- MySQL
- Redis
- 可用的 DeepSeek API Key

具体依赖版本以 `backend/requirements.txt` 为准。

### 2. 安装依赖

在项目根目录打开终端：

```bash
cd backend
python -m venv .venv
```

Windows PowerShell 激活虚拟环境：

```powershell
.\.venv\Scripts\Activate.ps1
```

安装依赖：

```bash
python -m pip install -r requirements.txt
```

如果项目使用的是项目根目录中的虚拟环境，请激活实际对应的虚拟环境后再安装依赖。

### 3. 配置环境变量

在 `backend/` 目录创建 `.env` 文件，根据项目当前的 `settings` 配置填写实际使用的数据库、Redis 和模型参数。

大语言模型相关变量包括：

```dotenv
LLM_API_KEY=你的DeepSeek_API_Key
LLM_MODEL=你的模型名称
LLM_BASE_URL=你的模型服务地址
```

以上均为配置占位示例。请以项目实际代码、DeepSeek 控制台及当前使用的模型服务配置为准。

不要将真实 API Key、数据库密码或其他敏感信息提交到 GitHub。

### 4. 初始化数据库与运行服务

先创建 MySQL 数据库，并按照项目现有的数据库初始化流程创建所需表；同时确认 Redis 服务正常运行。

进入 `backend/` 目录后，启动 FastAPI：

```bash
uvicorn main:app --reload
```

启动后访问：

- Swagger API 文档：`http://127.0.0.1:8000/docs`
- 根路径：`http://127.0.0.1:8000/`

首次运行前，请确保数据库、Redis、环境变量以及项目所需的向量模型配置均已准备好。
